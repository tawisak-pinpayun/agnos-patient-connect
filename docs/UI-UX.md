# แนวคิดการออกแบบ UI/UX

## หลักคิด

1. **ผู้ป่วยกรอกให้เสร็จได้เร็วที่สุด** — ฟอร์มแบ่งกลุ่มชัดเจน, ช่องบังคับมี `*`, ช่องไม่บังคับเขียนกำกับว่า "ไม่บังคับ" เพื่อลดความกังวล
2. **เจ้าหน้าที่ต้องเห็นการเปลี่ยนแปลงโดยไม่ต้องหา** — flash highlight ที่ช่องที่เพิ่งเปลี่ยน + badge สถานะ + progress bar
3. **ระบบต้องบอกความจริงเสมอ** — สถานะการเชื่อมต่อ, สถานะบันทึกอัตโนมัติ, และสถานะของผู้ป่วยแสดงให้เห็นตลอด ไม่ปล่อยให้เดา
4. **ไม่มีข้อมูลหาย** — auto-save ทุกครั้งที่พิมพ์ รีเฟรชแล้วยังอยู่

## Breakpoints และการจัดวาง

ใช้ breakpoint ของ Tailwind: `sm` = 640px, `lg` = 1024px

### มือถือ (< 640px)

| หน้า | การจัดวาง |
|---|---|
| Header | โลโก้ + สถานะ/ภาษาแถวบน, nav เต็มความกว้างแถวล่าง (`order-3 w-full`) ปุ่มกดง่ายด้วยนิ้ว |
| ฟอร์มผู้ป่วย | 1 คอลัมน์, การ์ดเรียงต่อกัน, **submit bar ติดขอบล่างจอ** (`fixed inset-x-0 bottom-0`) เห็นปุ่มส่งและ progress ตลอดโดยไม่ต้องเลื่อนหาสุดหน้า |
| หน้าเจ้าหน้าที่ | รายการเป็น card เรียงตั้ง 1 คอลัมน์, **กดแล้วไปหน้ารายละเอียดแยก** (`/staff/[sessionId]`) เพื่อได้พื้นที่เต็มจอ มีปุ่ม "กลับไปรายการ" |
| รายละเอียดผู้ป่วย | ช่องข้อมูล 1 คอลัมน์ |

**รายละเอียดที่ใส่ใจ**: `font-size: 16px` บน input/select/textarea เพื่อไม่ให้ iOS Safari zoom เองตอนโฟกัส (กลับเป็น 14px ที่ ≥640px)

### แท็บเล็ต (640px – 1024px)

| หน้า | การจัดวาง |
|---|---|
| ฟอร์มผู้ป่วย | **2 คอลัมน์** (`sm:grid-cols-2`) — ช่อง "ที่อยู่" กินเต็ม 2 คอลัมน์เพราะเป็น textarea |
| หน้าเจ้าหน้าที่ | รายการเป็น **grid 2 คอลัมน์** (`sm:grid-cols-2`) ใช้พื้นที่กว้างได้คุ้ม, ยังกดไปหน้ารายละเอียดแยก |

### เดสก์ท็อป (≥ 1024px)

| หน้า | การจัดวาง |
|---|---|
| ฟอร์มผู้ป่วย | จำกัดความกว้าง `max-w-3xl` จัดกลางจอ — ฟอร์มกว้างเกินไปอ่านยาก, submit bar เลิก fixed กลายเป็นการ์ดปกติท้ายฟอร์ม |
| หน้าเจ้าหน้าที่ | **Split view** — รายการซ้าย 1/3 (scroll แยก, `max-h-[calc(100dvh-14rem)]`) + รายละเอียดขวา 2/3 กดสลับผู้ป่วยได้โดยไม่เปลี่ยนหน้า |
| รายละเอียดผู้ป่วย | ช่องข้อมูล **3 คอลัมน์** (`xl:grid-cols-3`) เห็นข้อมูลทั้งหมดในจอเดียว |

> การสลับพฤติกรรมระหว่าง "ไปหน้าใหม่" กับ "split view" ทำผ่าน `useMediaQuery('(min-width: 1024px)')` ไม่ใช่แค่ซ่อนด้วย CSS — เพื่อไม่ให้ subscribe socket ซ้อนกันโดยไม่จำเป็น

## การสื่อสารสถานะ (Feedback)

| องค์ประกอบ | สิ่งที่บอก | ดีไซน์ |
|---|---|---|
| `ConnectionIndicator` | สถานะ WebSocket | เขียว = เชื่อมต่อแล้ว / เหลือง + spinner = กำลังเชื่อมต่อ / แดง = ขาดการเชื่อมต่อ |
| สถานะ auto-save | draft ถูกบันทึกหรือยัง | spinner "กำลังบันทึก..." → เครื่องหมายถูกสีเขียว "บันทึกอัตโนมัติแล้ว" |
| `StatusBadge` | สถานะผู้ป่วย | ฟ้า + ไอคอนดินสอ (pulse) = กำลังกรอก / เขียว + เครื่องหมายถูก = ส่งแล้ว / เทา + ไอคอน pause = หยุดกรอก |
| `ProgressBar` | กรอกครบกี่ช่องจากช่องบังคับ | ฟ้าระหว่างกรอก → เขียวเมื่อครบ 100% |
| `LiveField` flash | ช่องไหนเพิ่งเปลี่ยน | พื้นหลังฟ้าอ่อนจางหายใน 1 วินาที |

**สีสถานะเลือกให้แยกได้ด้วยไอคอนด้วย ไม่พึ่งสีเพียงอย่างเดียว** (ผู้ใช้ที่ตาบอดสีก็แยกได้)

## Accessibility

- ทุก input มี `<label htmlFor>` ผูกกับ `id` จริง
- `aria-invalid` เมื่อ validate ไม่ผ่าน + ข้อความ error มี `role="alert"`
- ค่าที่อัปเดตเรียลไทม์อยู่ใน `aria-live="polite"` เพื่อให้ screen reader อ่านการเปลี่ยนแปลง
- `focus-visible:outline` ชัดเจนทุกปุ่มและ input ใช้คีย์บอร์ดล้วนได้
- `motion-safe:` ครอบ animation ทั้งหมด — ผู้ใช้ที่ตั้ง `prefers-reduced-motion` จะไม่เห็น flash/pulse
- `<html lang>` เปลี่ยนตามภาษาที่เลือก
- `aria-current` บนการ์ดที่ถูกเลือกในรายการ

## Typography และสี

- **ฟอนต์**: Noto Sans Thai (subset `thai` + `latin`) รองรับทั้งไทยและอังกฤษด้วยฟอนต์เดียว น้ำหนัก 400–700
- **สีหลัก**: brand blue (`#1b70f0`) — โทนโรงพยาบาล/การแพทย์ ให้ความรู้สึกน่าเชื่อถือและสะอาด
- **พื้นหลัง**: `slate-50` ตัดกับการ์ดสีขาว ทำให้ขอบเขตแต่ละกลุ่มข้อมูลชัดโดยไม่ต้องใช้เส้นหนา
- **สีความหมาย**: เขียว = สำเร็จ, เหลือง = รอ, แดง = ผิดพลาด, เทา = ไม่ทำงาน

## สลับภาษา ไทย / อังกฤษ

- ปุ่มสลับอยู่ที่ header ทุกหน้า เห็นตลอด
- แปลครบทั้ง label, placeholder, hint, ตัวเลือกใน dropdown, และ **ข้อความ error**
- ทำได้เพราะ Zod schema เก็บ error เป็น **key** (`error.invalidPhone`) ไม่ใช่ข้อความตรง ๆ — ฝั่ง UI ค่อยแปลตาม locale ปัจจุบัน ทำให้ error ที่ส่งกลับจาก server ก็แสดงเป็นภาษาที่ผู้ใช้เลือกได้เช่นกัน
- จำค่าไว้ใน `localStorage` เปิดครั้งถัดไปได้ภาษาเดิม
